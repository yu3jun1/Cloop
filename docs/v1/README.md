# CLARITY Loop

Coop is a research framework for training and evaluating recursive-rollout (RRT) ensemble dynamics from frozen longitudinal MRI latents, linking predicted states to a separately trained censored-survival head, and testing receding-horizon replanning. It is intentionally offline by default and does not execute treatment.

The implementation keeps three evidence levels separate:

1. **Factual forecasting** conditions on recorded actions and recorded time intervals and scores future latent/outcome predictions.
2. **Observed replay** exposes only information available at each recorded observation and measures treatment-set agreement and system behavior. A recommendation never drives the historical next MRI.
3. **Independent synthetic closed loop** sends recommended actions to a non-medical toy environment whose transition code never calls the learned world model.

RRT, ensembles, and MPC are general methods. D1/D2 are internal controlled baselines and are not presented as a full reproduction of CLARITY. Planning uses an observational prognostic proxy, not an identified causal treatment effect.

## Real-data workflow

Global options must precede the subcommand.

`main_v1` requires the explicit JSON file configured by
`paths.latent_provenance`. During `prepare`, the encoder identity, frozen
status, null adapter, 768-D output, checkpoint path and SHA-256, extraction
protocol, source commit, and latent count are verified. The provenance hash is
stored in both the cache metadata and `run.json`.

Every usable `main_v1` timeline node must provide `mri_day_source` as
`observed`, `imputed_interior`, `imputed_leading`, or `imputed_trailing`.
Missing, explicitly `unknown`, or unrecognized values are audited as
`unknown`; a numeric date is never silently treated as observed. With the
required `data.require_mri_day_provenance: true` setting, both `doctor` and
`prepare` reject a main-protocol cohort if any usable timepoint is unknown.
The timeline must therefore be regenerated by its upstream data-preparation
pipeline when this provenance is absent; Cloop does not infer it from dates.
On success, source counts and affected transitions/H2/H3 windows are stored in
`run.json.audit.time_quality`.

```bash
PY=/home/tanyuejun/miniconda3/envs/py310/bin/python

"$PY" -m cloop --config configs/v1/default.yaml --paths configs/v1/server.yaml \
  --run brainiac_v1 doctor
"$PY" -m cloop --config configs/v1/default.yaml --paths configs/v1/server.yaml \
  --run brainiac_v1 prepare

CUDA_VISIBLE_DEVICES=7 "$PY" -m cloop --config configs/v1/default.yaml \
  --paths configs/v1/server.yaml --run brainiac_v1 train --suite dynamics \
  --variants baseline rrt ensemble rrt_ensemble --seeds 7 17 29

CUDA_VISIBLE_DEVICES=7 "$PY" -m cloop --config configs/v1/default.yaml \
  --paths configs/v1/server.yaml --run brainiac_v1 train --suite outcome --seeds 7 17 29

"$PY" -m cloop --config configs/v1/default.yaml --paths configs/v1/server.yaml \
  --run brainiac_v1 evaluate --suite all --split validation
"$PY" -m cloop --config configs/v1/default.yaml --paths configs/v1/server.yaml \
  --run brainiac_v1 freeze-protocol
"$PY" -m cloop --config configs/v1/default.yaml --paths configs/v1/server.yaml \
  --run brainiac_v1 evaluate --suite all --split test
"$PY" -m cloop --config configs/v1/default.yaml --paths configs/v1/server.yaml \
  --run brainiac_v1 report
```

For a complete-epoch recovery, repeat the matching training command with `--resume`. `last.pt` includes the model, optimizer, early-stopping state, data generator, and Python/NumPy/Torch RNG states. It is removed after the selected training suite finishes.

CLI `train` and `synthetic` commands mirror stdout and stderr to
`logs/v1/<run>.log` while retaining terminal output. Repeated or resumed commands
append timestamped sections to the same per-run log. The repository-level
`logs/v1/` directory is ignored by Git and is intentionally separate from the
strict flat artifact directory under `outputs/v1/`.

`freeze-protocol` requires validation-derived uncertainty scales, an existing
`models.pt`, and no outstanding `last.pt`. It records the SHA-256 of
`models.pt` in `run.json`. After freezing, `prepare`, all training (including
`--force-task`), and any other model/preprocessing replacement are rejected.
Every test evaluation verifies the stored hash before loading models, so a
modified or missing `models.pt` invalidates the run. Model-read-only evaluation
and `report` remain allowed.

The optional legacy regression protocol must be a separate run. It uses
`LegacyOneStepDynamics`, whose LayerNorm, time MLP, single-token GRU,
residual MLP, parameter names, and final-layer initialization match the
historical Stage 1 model:

```bash
"$PY" -m cloop --config configs/v1/default.yaml --paths configs/v1/server.yaml \
  --run brainiac_legacy --protocol legacy_stage1 prepare
```

Legacy preprocessing computes train-only latent statistics in NumPy
`float64`, applies the minimum-standard-deviation rule, and stores the result
as `float32`. A single Baseline or RRT model uses the requested training seed
directly (for example, seed 17 uses member seed 17); an ensemble uses
`training_seed * 1000 + member_index` (17000, 17001, ...). Actual member seeds
are recorded in both `models.pt` and `metrics.json`.

## Independent synthetic experiment

```bash
CUDA_VISIBLE_DEVICES=7 "$PY" -m cloop --config configs/v1/default.yaml \
  --paths configs/v1/server.yaml --run synthetic_v1 synthetic --seeds 7 17 29
```

Its `A0/A1/A2` actions and state variables have no medical meaning. Results test feedback, replanning, perturbation recovery, constraints, and inference budgets only.

Dynamics metrics call cosine similarity `CosSim@1/2/3` (larger is better).
Paired relative improvements are reported as `baseline_vs_rrt`,
`ensemble_vs_rrt_ensemble`, and `baseline_vs_rrt_ensemble`. When clinical
rules are disabled, structural-rule violation rate is `null`, not zero.

Observed replay reports two distinct behavior metrics.
`sequential_action_change_rate` compares the current recommendations at
adjacent visits. `plan_revision_rate` instead compares an MPC recommendation
after re-observation with the action previously planned for that same future
stage. It is reported only for `mpc_ensemble`, `mpc_rrt_ensemble`, and
`mpc_rrt_ensemble_unc`. It is `null` with an explicit reason for `fixed_plan`,
`greedy`, and `frequency`; those methods must not fabricate a zero revision
rate. Plan revision is a behavioral response to new observations, not a score
where a larger value is inherently better.

## Artifacts and privacy boundary

Each run directory is flat and contains at most:

- `run.json` — resolved configuration, provenance, patient split IDs, audit, protocol state, and frozen model hash;
- `models.pt` — best model states, actual ensemble member seeds, and train-only preprocessing;
- `last.pt` — the sole temporary resume point;
- `metrics.json` — training history and aggregate metrics;
- `predictions.jsonl` — optional idempotent per-window/per-decision records;
- `report.md` — the one human-readable report.

No per-patient directories, epoch checkpoints, branch tensors, API keys, raw prompts, MRI arrays, or online calls are created by default. External LLM payloads are constrained to catalog IDs and sanitized summaries; only the offline catalog and fake provider are required in v1.

See [`clarity_loop_from_scratch_experiment_design.md`](clarity_loop_from_scratch_experiment_design.md) for the registered protocol, metric definitions, data-quality rules, and interpretation boundaries.
